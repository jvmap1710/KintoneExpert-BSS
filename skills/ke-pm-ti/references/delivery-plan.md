# Delivery plan template

| Item | Content |
| --- | --- |
| Business outcome | What measurable outcome is expected? |
| Scope / exclusions | What is included and explicitly excluded? |
| Stakeholders | Sponsor, process owner, PIC, approver, IT owner |
| Phases | Discovery → Design → Build → UAT → Deploy → Handover |
| Deliverables | BRD, solution blueprint, build backlog, test pack, handover |
| Risks / dependencies | Data, policy, access, integration, timeline |
| Decisions needed | Owner, decision, deadline, status |

## Phase plan

| Phase | Outcome / deliverable | Entry condition | Exit gate | Owner | Status |
| --- | --- | --- | --- | --- | --- |
| Frame | Scope and success baseline | Project identity known | Outcome, scope, owner, KPI agreed | Ti | ACTIVE |
| Discover | Requirements and acceptance | Sources available | Rules, exceptions, acceptance IDs ready | Teo | TODO |
| Design | Build-ready blueprint | Requirements baselined | Architecture risks and decisions resolved | LauDe | TODO |
| Build | Staged/deployed change | Design approved | Read-back, deploy, runtime and Quick Verification state clear | LeBa / Mit | TODO |
| Validate | Smoke/UAT/release evidence | Scope complete and test approved | Evidence-based recommendation issued | Mit | TODO |
| Close / improve | Handover and backlog | Acceptance recorded | Ownership, support and follow-up agreed | Ti | TODO |

Use `project-control-template.md` for live milestones, RAID, decisions, and the
prioritized backlog.
