# Requirement intake

| Area | Capture |
| --- | --- |
| Objective | Problem, target outcome, KPI |
| Trigger and frequency | Who starts it, when, volume/SLA |
| Actors | Requester, PIC, checker, approver, admin |
| Current process | Steps, channels, pain points, attachments |
| eForm | Fields, data types, required fields, defaults, lookup/master data |
| Rules | Validation, calculation, exception, notification |
| Approval | States, transitions, role at each step, return/reject rules |
| Outputs | Views, reports, exports, notifications, audit need |
| Acceptance | Happy path, edge cases, measurable completion criteria |

## Selective context prompts

Ask only for information that is missing and material; skip or combine these
prompts as appropriate.

- Audience, outcome, and depth: Who will use the analysis, what decision or
  understanding should it support, and how much detail is useful?
- One common case: From trigger to finish, who does what, when, and in which
  App or other tool?
- Data and system boundaries: Which data is maintained as master/reference
  data versus per request, and which important actions happen outside Kintone?

Summarize the known flow and material uncertainties, then continue with
independent analysis. Do not repeat known context or treat elapsed time or
silence as approval.
